# Port 287 · исходный приказ, отряд и эффект

Проверены RotWK 2.01, BFME2 1.06 (донор) и эффективные INI из архива Ennorath 1.9.8.3. Для двух наблюдений владельца результат разный: у «Натиска» обнаружился **другой CommandButton у выбранного отряда**. Для плаща именно `MirkwoodWarriorHorde` архив и наблюдение владельца пока не удаётся согласовать. Вывод о поведении кнопки в установленном оригинале из одного архива не делается.

## 1. На чьей панели находится кнопка (обе редакции)

В `SelectionTranslator::leftClick` (RW 0x83C340) вызов `iterateDrawablesInRegion` передаёт `addDrawableToList` (RW 0x7108F2). Это **один** callback и для точки (RW 0x485B80, вызов RW 0x485D6F), и для рамки (обход drawable в той же функции). DONOR BFME2 0x70F14C (`GameClient/Rva0030F14CSelect.cpp`); ветка сверена на обоих `game.dat`.

- RW 0x7108F9–0x71096B: список, битовые маски типа drawable, специальные запреты и `CanSelectDrawable`. RW 0x71097D–0x7109CC: проверка тумана и невидимого drawable, включая принадлежащий отряду (`getHordeObject(false)`, RW 0x693A1A). Это ещё не выбор представителя.
- RW 0x7109CE–0x710A09: поиск объекта по **`Object + 0x78` (producer ID)**, независимо от `ContainedBy`. Нет ID, объект по нему не найден либо не `HORDE` — продолжается обработка исходного drawable. Если найденный `HORDE` имеет `UNSELECTABLE` (статус 3), отвергается весь кандидат; иначе callback заменяет и объект, и drawable на отряд. BFME2: та же проверка в 0x70F228–0x70F263.
- RW 0x710A0C–0x710A4F: далее читается `SelectionPriority` уже представителя и в список заносится его drawable. Путь двойного щелчка (RW 0x81F791) и объект-цель приказа под этот callback не подпадают.
- В порте `HudObjects::pickForSelection` подменяет через `ContainedBy`, а рамка читает `ProducerID` только внутри проверки `ContainedBy`. Поэтому обычный сформированный отряд уже выбирает правильный набор, но боец, сохранивший ID отряда без текущего `ContainedBy`, может открыть свою панель со старой кнопкой. Это реальное разделение состояний: `HordeContain::removeMember(keepSlot)` очищает связь контейнера, сохраняя слот; `HordeContain::addToContain` пишет ID производителя (RW 0x872D0A). Исправление должно применять правило RotWK к обоим путям выделения, не менять выбор цели и не перенаправлять каст старой кнопки.

## 2. От доступности до исполнения

| Этап | Что читает и делает RotWK 2.01 |
|---|---|
| `getCommandAvailability`, RW 0x942733, ветка RW 0x943343 | `ShowButton`, шаблон и активный хозяин; перебирает науки до первой принадлежащей игроку, без подходящей скрывает, выключенная/скрытая наука запрещает. Проверяет `PreventActivationConditions` и `UnitCost` у интерфейса отряда (RW 0x94341F–0x943480). |
| Поиск в той же ветке | RW 0x943486 ищет свой модуль по шаблону через RW 0x68C26D. RW 0x94349A–0x9434F4 отдельно может сменить шаблон по команде цепочки `SpecialAbilityUpdate`, найденного по типу (RW 0x68C461 / RW 0x851371). Без модуля цикл `CommandTrigger` смотрит только кнопки `SPECIAL_POWER`; выходы из цикла ведут к доступности `1` (RW 0x9434F7–0x943564 → RW 0x942FF1). Это не исполнение. С модулем: требования, готовность, процент перезарядки, условия модели и ветка `BattlePlan` (RW 0x943569–0x943606). |
| `processCommandUI`, RW 0x940435 | Кнопка должна быть кликабельной. RW 0x94070F — проверка готовности специальной команды; RW 0x940877 — адресные `Options` переключают режим выбора цели. Для обычного левого нажатия без цели RW 0x94153C посылает `MSG_DO_SPECIAL_POWER` со своим ID силы и `Options`, оба ID объектов нулевые; цикл RW 0x94157D–0x941618 добавляет команды из `CommandTrigger` с типом `SPECIAL_POWER`. Правая кнопка для `AutoAbility` (RW 0x9414E7–0x941537) отправляет иной приказ, не каст. `TriggerWhenReady` — ветка уже установленного на объекте `AutoAbilityBehavior`, не самостоятельный эффект кнопки (RW 0x85DB26). DONOR BFME2 0x939A65 (`ControlBarCommandProcessing.cpp`). |
| Симуляция | RW 0x77A42C с нулевым ID источника берёт выделение игрока; RW 0x76F5DB идёт по выбранной группе, а не её `InitialPayload`. Ветка `OK_FOR_MULTI_EXECUTE` пропускает выбор старшего героя; RW 0x82D5DA проверяет тип, местность, `UnitCost`, собственный модуль, готовность и требования; оба используемых безадресных типа проходят финальную таблицу. Адресный вариант RW 0x82D925 тоже требует модуль. RW 0x68E5A3 / RW 0x68E67A проверяют disabled, доступность RW 0x7B1D79 и ищут интерфейс; без него возврат, с ним — проверка формации RW 0x68CB85 и слот каста. RW 0x68C26D проходит только массив модулей объекта и принимает первый, чей интерфейс заявляет этот шаблон. DONOR BFME2 0x68BB9E (`Object_getSpecialPowerModule.cpp`), 0x68DF48 (`ObjectDoSpecialPowerCommands.cpp`) и 0x76D869 (`AIGroup.cpp`). |

## 3. Ангмар: «Натиск»

В `commandset.ini` кнопки с `SpecialAbilityAngmarCharge` принадлежат **старым наборам отдельных бойцов**. У фактически выбираемых `AngmarSnowTrollHorde` и `AngmarDarkDunedainHorde` в том же слоте — свои безадресные кнопки `SpecialAbilityChargeNoAim`. Набор тёмных дунэдайн, выдаваемый апгрейдом, также использует новую кнопку. Проверены `InitialPayload`, варианты `ChildObject`, объявления самих бойцов и активные включения: соответствующие `SpecialPowerModule` уже есть на обоих отрядах (и на бойцах, хотя меню бойца их не вызывает); старые блоки натиска в этих определениях закомментированы. Нет `CommandTrigger`, который связывал бы старую кнопку с новой.

- Стартёр разблокируется вторым уровнем: `UnpauseSpecialPowerUpgrade` (RW 0x8D27AA, найденный модуль через RW 0x68C26D). `SpecialPowerModule::doSpecialPower` (RW 0x8980A3) проверяет паузу/disabled, инициирует действие (RW 0x897E87) и при `UpdateModuleStartsAttack = No` сразу запускает RW 0x897987. DONOR BFME2 0x89490F (`SpecialPowerModuleDo.cpp`).
- RW 0x897987 запускает перезарядку и ветку модификатора. Без `AttributeModifierAffectsSelf` берутся только прошедшие фильтры из запроса по радиусу; при `AffectsSelf` для не-отряда добавляется сам кастер, если его ещё нет, а для `HORDE` запрашивается интерфейс RW 0x68C866 и список бойцов (RW 0x897C5A–0x897CBB). Отсутствие этого интерфейса не превращает отряд в одиночную цель. RW 0x8977BF проверяет применимость к каждому кандидату, RW 0x89763B применяет список; в списках натиска есть `DAMAGE_MULT`. У дунэдайн есть и отдельный `WeaponModeSpecialPowerUpdate`; его модификатор движения — не источник увеличения урона.
- Основной каст и модификатор уже работают, когда выбран именно отряд (строки `PASS` в исходном `MATRIX.tsv`, без заявления о новом игровом прогоне). Задача порта здесь — довести выбор отряда до правила RW, а в матрице направить проверку к его реальной кнопке вместо старого ID силы отдельного бойца. Пустой старый модуль нельзя чинить поиском по похожим именам или типу силы.

## 4. Лихолесье: что воспроизводится по имеющимся данным

`MirkwoodWarriorHorde` — прямой `Object`, не наследник стражей. Проверены наборы (`commandset.ini` и `includes/commandset.inc`), кнопка (`includes/commandbutton.inc`), шаблон силы, объект, `InitialPayload` (`MirkwoodWarrior`), знаменосец, действующие `#include`, дочерние и призванные варианты, апгрейды и Lua-списки этих объектов. В архиве активная кнопка `Command_SpecialAbilityElfCloakTroopsWatcher` не имеет `CommandTrigger`; её флаги автокаста не содержат эффекта, а у этих шаблонов не найден ни стартёр `SpecialAbilityElfCloak`, ни `ToggleHiddenSpecialAbilityUpdate` для него. Отдельный `MirkwoodWachterPfadeHorde` и варианты стражей используют **ту же кнопку** со стартёром, `ToggleHiddenSpecialAbilityUpdate` и `InvisibilityUpdate`. Это разные шаблоны; вывод об ошибке в проверке владельца из этого не следует.

У стражей каст действительно достигает эффекта: `SpecialPowerModule` инициирует одноимённый апдейт; RW 0x8B1909 (первый триггер) выбирает `unhide` RW 0x8B19AC или `hide` RW 0x8B1A70. `hide` требует условий и AI, приостанавливает отсчёт, выставляет `HIDDEN`, активирует первый `InvisibilityUpdate` через RW 0x8A7049; `unhide` снимает флаги, возобновляет отсчёт и выключает модуль. DONOR: `ToggleHiddenSpecialAbilityUpdate.cpp` и `ToggleSpecialAbilityUpdateSlot17.cpp`. Для теста форма с модулем — положительный контроль, не объяснение поведения `MirkwoodWarriorHorde`.

**Проверить в оригинале:** в той же установке/режиме, где виден эффект, выбрать именно `MirkwoodWarriorHorde` (не `MirkwoodWachterPfadeHorde`), нажать плащ без другой действующей способности рядом и подтвердить внутреннее имя выбранного отряда и фактически загруженный путь к его INI (включая карту, переопределения и патчи). Для архивной конфигурации путь RW обрывается на отсутствии модуля; для наблюдения владельца источник эффекта пока не доказан. Не помечать эту строку как BY-DESIGN и не дописывать силу по имени.
