| S-7444 | code | `micropathToPosition` (`RW 0x00663EF4`, AI vslot `0x22C`) и `appendPositionToLocomotorPath` (`RW 0x0066708E`, AI vslot `0x218`) не перенесены: у порта для них нет вызывающего (общее условие (б)) |

## Почему стоп

Оба — внутренние помощники пути собственного класса (`AIUpdateInterface`), поэтому условия (а), (в) и (г) выполнены. Не выполнено (б): в порте нет
вызывающего, которому они нужны, и заводить их «впрок» запрещено (код без вызывающего).

Тела прочитаны по `game.dat`:

- `RW 0x0066708E` (`appendPositionToLocomotorPath(pos, layerish)`): `vslot 0x214` (`RW 0x662934`, цель = позиция с путём), затем, если путя (`AI + 0x140`)
  нет, `operator new(0x28)` + конструктор `Path` (`RW 0x765A1A`), `Path::appendPoint` (`RW 0x665429`) от позиции объекта (`Object + 0x38`), байт `Path + 0xC = 1`,
  `Path::0x76578C(value)`, `ThePathfinder` (`RW 0x680A75`) и снова `RW 0x665429` с новой точкой.
- `RW 0x00663EF4` (`micropathToPosition(dest)`): `Pathfinder`-вызов по объекту (`RW 0x6F0741`), `destroyPath` (`RW 0x66276B`), путь, доходящий до цели
  (`RW 0x6F74D0`), `AI + 0x140` = путь, тип цели 4 (`AI + 0x1FC`), позиция цели (`AI + 0x200`).

Вызывающие в RotWK — состояния следования по пути и приказы их ставящие: слот `0x218` вызывают 11 мест (`0x4888CC`, `0x876026`, `0x87977F`, `0x8BF3A2`,
`0xA95878`, ...), слот `0x22C` — 6 (`0x677938` внутри самого `AIUpdateInterface`, `0x7A022F`, `0x59B0E7`, `0x448217`, `0x48C6FB`). В порте путь целиком
строят `AIMover::computePath` / `computeQuickPath` (`RW 0x665C33` / `RW 0x665A83`), а маршрутизация приказов, которая приводит к этим состояниям, —
лейн Port 239 (стоп S-222: порт исполняет только move / idle / follow-path / busy). Перенос без той маршрутизации дал бы недостижимый код.

Что нужно задаче-продолжению (Port 239, S-222): когда приказ `AICMD_FOLLOW_PATH_APPEND` / путь по точкам будет маршрутизирован, вызвать из состояния
следования `appendPositionToLocomotorPath` (`RW 0x0066708E`) и из быстрого выхода `micropathToPosition` (`RW 0x00663EF4`) — тела выше.
